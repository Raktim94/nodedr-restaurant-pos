# Engineering and security audit, November 2026

Scope: `master` at v1.31.0 (backend NestJS/Prisma, web Next.js, Capacitor mobile offline layer).
Method: read-only review, then fixes with regression tests. Every status below says what was actually run.
Not done in this pass: NFC (NTAG 424 DNA) ordering, the new table state machine, the mobile redesign and any
deployment. They are separate releases and are listed under "Open".

Skills: the "Cloudflare Security Audit" and "Google Modern Web Guidance" skills were not available on the
machine, so neither was used. OWASP guidance and the NestJS/Prisma/Next.js documentation were the references.

## Findings

| ID | Severity | Finding | Status |
|---|---|---|---|
| A-01 | Medium | 14 `pnpm audit --prod` advisories (hono, @hono/node-server, node-forge, glob, minimatch), transitive; the lockfile pinned old versions although the override range allowed the fix | FIXED AND VERIFIED: overrides raised, audit now 0; build, 412 unit tests, web build pass |
| A-02 | Medium | No CI ran typecheck, unit tests, e2e or the dependency audit. e2e suites are opt-in by env flag so they were never run by default | FIXED AND VERIFIED: `.github/workflows/ci.yml`; first run on GitHub green |
| A-03 | High (unverified claim) | August report finding #3: cross-tenant `tableId`/`customerId` on orders, reservations, waitlist, gift cards was never live-tested | VERIFIED NOT VULNERABLE: `cross-tenant.e2e-spec.ts` (10 tests, each rejection has a positive control) |
| A-04 | Medium | Admin password change did not end the user's existing sessions (JWT only checked `isActive`); a stolen cookie lived 12h | FIXED AND VERIFIED: `users.sessionsValidFrom`, REST strategy and realtime gateway; tokens carry a millisecond issue time (the first version used the 1-second JWT `iat` and revoked a sign-in made in the same second as the change; CI caught it); unit + e2e |
| A-05 | Medium | Offline sale `soldAt` came from the phone clock with no bounds and became `createdAt`; a wrong clock misfiled sales into future or closed periods | FIXED AND VERIFIED: future clamped to receive time and flagged, older than `OFFLINE_SALE_MAX_AGE_DAYS` (90) refused as `SALE_TOO_OLD`; unit + e2e |
| A-06 | Medium | Mobile order, kitchen and offline sale numbers came from a read-then-write counter in two transactions; 25 concurrent calls produced 1 unique number | FIXED AND VERIFIED in headless Chrome (25/25 unique); regression script `mobile/test/idb-counters.chrome.cjs` (manual, not in CI) |
| A-07 | Low | Lint: 876 errors (846 Prettier, 28 redundant assertions) | NOT FIXED: formatting only, not mass-reformatted in billing code |
| A-08 | Low | Raw SQL in `sync.service.ts` interpolates table names | NOT A VULNERABILITY AS READ: names come from a catalog allowlist; no injection test written |
| A-09 | Low | Attachment type check trusts the client MIME type (stored in DB, served with nosniff) | NOT FIXED: low risk |
| A-10 | Low | Logout only clears the cookie; the JWT is not individually revocable | NOT FIXED: password change now revokes; per-token denylist not built |
| A-11 | Info | One full e2e run failed in `aggregator-webhook` (4 tests), then passed 4 times in a row and alone; output was not captured | UNEXPLAINED, intermittent |
| A-12 | Info | e2e leaves stray files in `apps/backend/uploads` | NOT FIXED |

Confirmed good (sampled, not exhaustive): branch/restaurant scoping on tables, customers, users, ratings writes;
Helmet, global and per-route throttling, HMAC webhook verification with `timingSafeEqual`, idempotent payments
and offline sales (DB unique `(branchId, clientRequestId)`), `JWT_SECRET` strength check, CORS never `*`.

## Also shipped in this pass

Stock Journal: optional batch quality inspection (own `production.quality` permission, audit trail, "Not recorded"
by default), menu selling price frozen at posting, fuller reports with voucher drill-down, desktop side-by-side
Source/Destination view. See `docs/STOCK-JOURNAL.md`. CI also caught a missing default grant of the new permission
on freshly seeded databases; fixed. Lesson: verify on a freshly migrated and seeded database, not only a long-lived one.

## Checks run

328 passed on a fresh database, and the GitHub CI run on master is green. Mobile offline layer: 51 passed. Web build passed.
Not run: mobile device tests, iOS/Android builds, Lighthouse, load tests, any deployment.
